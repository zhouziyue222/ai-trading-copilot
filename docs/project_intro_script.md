# AI Trading Copilot 项目介绍稿

## 3 分钟面试介绍版

面试官您好，我想介绍的项目是 AI Trading Copilot，这是一个面向美股和美股 ETF 投资者的本地 AI 交易辅助决策系统。它的核心目标不是自动下单，而是帮助用户围绕自己的自选订阅池，完成机会扫描、交易计划生成、v2 风控限额和可解释复盘。

这个项目的背景是，很多主动投资者会关注几十只股票，但真正做决策时经常遇到三个问题：第一，行情、新闻、技术位置和组合风险分散在不同工具里；第二，交易计划容易被情绪影响，比如追高或者临时加仓；第三，AI 给出的建议如果没有硬规则约束，就很难被信任，也很难复盘。所以我把产品定位成一个“订阅池驱动的交易 Copilot”，只分析用户已经关注的标的，并且所有交易计划都必须通过风控规则。

从用户流程看，用户先维护一个订阅列表，比如 AAPL、MSFT、CRCL，并填写关注理由和目标动作。然后用户选择要分析的标的、分析模块、交易日期和回看天数。系统会进入一条多智能体工作流：新闻情绪分析师通过 Finnhub 获取市场新闻、社交媒体情绪和财报日历；技术分析师同步输出个股、板块代理和美股大盘三个维度的均线、MACD、RSI 与趋势状态；基本面分析师调用财务数据和基本面 RAG 检索。Trader Agent 综合证据生成结构化交易计划，包括入场逻辑、止损、目标位、目标仓位和失效条件。随后 Risk Manager 按 ai-hedge-fund v2 风格对目标权重做单标的上限和组合总敞口 clamp；Portfolio Manager 再把风控后的 final weight 转成 hold、buy、sell、reduce、short 或 cover 建议。系统只输出组合决策，不提交券商订单。

我认为这个项目比较有产品价值的地方有三点。第一，它不是泛泛地问 AI 买什么，而是把机会来源限制在用户订阅池里，符合真实投资者的工作习惯。第二，它把 AI 的灵活分析和确定性风控结合起来，LLM 可以参与解释和复核，但不能绕过 v2 风控限额。第三，它有完整的可追踪机制，每次运行都会生成节点状态、阶段报告和审计报告，用户可以知道每一步为什么这样判断，也可以用于后续复盘。

目前 MVP 已经支持 CLI 和 Web UI 两种入口。Web UI 是三栏工作台：左边管理订阅池，中间配置分析任务，右边查看运行进度和报告。系统默认是 simulation 模式，不会直接向券商下单；即使进入 Live 模式，也必须由用户显式确认，UI 中的 live portfolio 只作为只读组合上下文。

如果从产品经理角度总结，我在这个项目里重点做的是把一个高风险、高不确定性的 AI 金融场景拆成可控流程：先明确用户画像和交易边界，再定义订阅池、情绪面、技术面、基本面、交易计划和风控规则这些核心对象，最后通过报告和审计建立信任。后续我会优先优化三件事：一是提升报告摘要的可读性；二是加入关键事件和接近支撑位提醒；三是增加回测和复盘指标，验证多维分析和风控规则是否真的提升了决策质量。

## 1 分钟精简版

AI Trading Copilot 是一个美股和 ETF 的 AI 交易辅助决策系统。它不是自动下单工具，而是帮助用户围绕自己的自选订阅池，完成机会扫描、交易计划、风控检查和复盘报告。

用户先维护关注标的，然后选择分析模块启动任务。系统会通过新闻情绪、技术位置、基本面分析、交易计划、v2 风控限额和 Portfolio Manager 等 Agent 形成一条决策链。比如它会先判断个股、板块和大盘的技术状态，再结合新闻情绪、关键事件和基本面评分，生成包含止损、目标位和仓位的交易计划。之后 Risk Manager 会把目标权重限制在单标的和组合总敞口边界内；资格不合格的请求保持当前仓位不动，超限请求会被调整到允许权重。

这个项目的产品亮点是把 AI 建议约束在确定性规则里：AI 负责分析和解释，Risk Manager 负责权重边界，Portfolio Manager 负责最终组合建议。每次运行都有状态追踪、阶段报告和审计报告，用户能看到每一步为什么得出这个结论。MVP 已经支持 CLI 和 Web UI，并且不会直接下真实订单。

## 面试追问回答要点

如果被问“为什么要做订阅池驱动”，可以回答：

订阅池是为了降低 AI 过度发散和用户注意力分散的问题。真实投资者通常不是每天从全市场随机找股票，而是维护一批有研究基础的关注标的。把机会限定在订阅池里，可以让产品更贴近真实工作流，也能减少不必要的推荐风险。

如果被问“AI 输出不可靠怎么办”，可以回答：

这个项目没有把 LLM 当成最终决策者，而是把它放在结构化流程里。交易计划必须满足 Pydantic 模型约束，并且要经过确定性的资格门槛和 v2 风控限额。比如标的不在订阅池、使用期权或杠杆，会保持当前仓位不动；仓位或总敞口过高，会被 Risk Manager clamp 到允许权重，AI 的解释不能覆盖这些限制。

如果被问“怎么衡量产品效果”，可以回答：

我会从效率、质量和安全三个方向衡量。效率看一次订阅池扫描耗时和用户从启动到决策的时间；质量看机会状态与后续走势的匹配度、交易计划完整率、复盘后可复用的记忆数量；安全看风控调整命中率、资格保持不动命中率、Live 模式误触发次数以及用户对报告可解释性的满意度。

如果被问“你作为产品经理做了什么”，可以回答：

我会强调自己把模糊需求拆成了产品对象和流程：定义目标用户、交易画像、订阅池、机会状态、交易计划、风险规则和执行状态；设计从订阅管理到报告复盘的用户路径；明确 MVP 边界，尤其是默认模拟执行和不自动下单；并用报告、审计和状态追踪解决 AI 产品的可解释性和信任问题。

如果被问“下一步怎么迭代”，可以回答：

短期会优化 UI 中文文案和报告摘要，让用户更快读懂结论；中期加入接近机会时的提醒能力和不同交易画像模板；长期会引入回测与复盘指标，持续验证并扩展 SQLite 长期记忆知识库。
