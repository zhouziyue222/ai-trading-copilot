# AI Trading Copilot PRD

## 1. 产品概述

产品名称：AI Trading Copilot

产品定位：面向美股与美股 ETF 投资者的订阅池驱动型 AI 交易辅助决策工具。它把用户自选标的、行情与组合信息、多智能体分析、v2 风控限额、Portfolio Manager 组合决策和可解释报告整合到一个本地 Copilot 工作流中，帮助用户判断“哪些已关注标的接近可交易机会，以及最终应调整到什么组合权重”。

一句话价值：从“看很多股票但难以形成纪律化决策”，升级为“只围绕自选池进行结构化机会扫描、风险复核和可追踪复盘”。

重要边界：本产品不是自动交易系统，默认使用模拟执行模式，不直接下达券商订单；Live 模式也必须经过用户显式确认，且 UI 仅把 live portfolio 作为只读上下文。

## 2. 背景与问题

目标用户通常会维护一批自选股或 ETF，但在实际交易中存在几个高频问题：

- 信息分散：行情、新闻、技术位置、组合风险和交易计划分散在多个工具中。
- 决策不一致：用户容易因为短期波动、追涨情绪或临时消息偏离原定交易风格。
- 风控滞后：止损、仓位、回撤和禁用交易品类等约束往往在下单前才被人工检查。
- AI 输出不可控：纯聊天式投资建议缺乏结构化输入、硬规则校验和审计记录。
- 复盘难沉淀：每次分析的原因、风险和结果没有形成可检索的交易记忆。

本项目通过“订阅池限定机会来源 + 多分析模块 + v2 风控权重约束 + Portfolio Manager 组合决策 + 报告追踪”的方式，把 AI 从泛化建议工具约束成一个可解释、可审计、可复盘的交易辅助系统。

## 3. 目标用户

核心用户：有一定交易经验、关注美股/ETF、偏中短线波段交易的个人投资者。

典型画像：

- 交易风格：swing trading，偏好上涨趋势中的回调机会。
- 风险偏好：balanced plus，接受一定波动，但要求明确止损和仓位边界。
- 投资范围：美股、美股 ETF。
- 禁用工具：杠杆品种、期权。
- 风控纪律：单标的默认仓位 10% 到 25%，最高不超过 50%；组合最大回撤阈值 25%。

次级用户：

- 需要快速筛选自选池机会的主动投资者。
- 需要把个人交易规则产品化、流程化的量化或半自动交易爱好者。
- 想评估 AI Agent 在金融辅助决策场景中可控性的产品或技术团队。

## 4. 产品目标

业务目标：

- 提升用户从自选池中发现可交易机会的效率。
- 降低非纪律化交易、追高交易和过度仓位带来的风险。
- 让每次分析过程可解释、可追踪、可复盘。

用户目标：

- 快速知道订阅标的处于观察、接近机会、可行动、风险升高或不适配状态。
- 获得结构化交易计划，包括入场逻辑、止损、目标位、仓位、失效条件。
- 在决策前看到 Risk Manager 对目标权重的资格检查、单标的上限和总敞口调整。
- 通过 Web UI 或 CLI 启动分析，并查看进度、报告和审计文件。

MVP 成功指标：

- 机会扫描完成率：订阅标的批量分析任务成功完成比例。
- 风控调整准确率：不符合订阅池或禁用工具的请求保持当前仓位不动，超出仓位或总敞口限制的请求被 clamp 到允许权重。
- 报告可用率：每次运行产出 run_status、run_audit 和核心阶段报告。
- 用户决策耗时：从选择标的到拿到交易计划和风险结论的时间。
- 可解释满意度：用户能从报告中理解为什么推荐观察、等待、行动、调整权重或保持不动。

## 5. MVP 范围

已实现范围：

- 用户画像与订阅池领域模型。
- JSON 本地订阅池存储，支持新增、删除、更新状态。
- 订阅状态机，覆盖 observing、near_opportunity、actionable、risk_elevated、not_compatible。
- 行情适配器，支持 Futu OpenD、yfinance 及 OHLCV CSV 解析。
- 多智能体分析链路，包括新闻情绪、三维技术位置、基本面分析、交易计划、v2 风控限额、Portfolio Manager 组合决策、运行解释。
- Risk Manager 资格门槛与 v2 限额，覆盖订阅池、市场类型、禁用品种、单标的上限和组合总敞口。
- Portfolio Manager 将风控后的 final weight 转为组合建议；系统不向 Futu 或其他券商提交订单。
- RAG 记忆，以 JSONL 存储交易复盘经验，单次最多检索 5 条。
- CLI 和 FastAPI Web UI。
- 运行追踪与报告输出，包括节点状态、阶段报告和审计报告。

暂不包含：

- 自动向券商提交真实订单。
- 盘中实时高频交易。
- 期权、杠杆 ETF 或复杂衍生品策略。
- 多用户账号体系、云端同步和权限管理。
- 投资收益承诺或个性化财务建议。

## 6. 核心用户流程

1. 用户维护订阅池：添加 AAPL、MSFT、CRCL 等关注标的，填写关注理由和目标动作。
2. 用户选择分析范围：从订阅列表勾选标的，或手动输入标的。
3. 用户选择分析模块：新闻情绪、技术位置、基本面分析，可按需组合。
4. 系统拉取或解析行情数据：根据回看天数和交易日期形成价格序列。
5. 新闻情绪分析：获取市场新闻、社交媒体情绪和财报日历，输出情绪评分与关键事件预警。
6. 技术与基本面分析：技术分析同步判断个股、板块代理和美股大盘状态，基本面分析调用财务数据和 RAG 检索。
7. Trader Agent 先判断市场状态，再综合技术、情绪和基本面证据生成交易计划：输出方向、入场逻辑、止损、目标位、仓位和失效条件。
8. Risk Manager 对目标权重执行 v2 风控：资格不合格则保持当前仓位，超限则输出 clamp 后 final weight。
9. Portfolio Manager 根据 final weight 与当前权重的差值生成 hold、buy、sell、reduce、short 或 cover 建议。
10. 系统生成报告：用户在 UI 查看进度、节点状态、各阶段报告和 run_audit。

## 7. 功能需求

| 模块 | 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- | --- |
| 订阅池管理 | P0 | 用户可以新增、删除、编辑关注标的，标的限定为美股或美股 ETF | 标的自动标准化为大写，重复订阅被拒绝，变更写入 JSON |
| 分析任务创建 | P0 | 用户可以选择订阅标的、手动输入标的、选择分析模块、设置交易日期和回看天数 | API 返回 run_id，生成独立报告目录 |
| 新闻情绪分析 | P0 | 通过 Finnhub 获取市场新闻、社交情绪和财报日历 | 输出 sentiment_score、key_events、alerts 和 data_availability |
| 技术位置分析 | P0 | 计算均线、MACD、RSI、支撑位、近期高点、回撤幅度，并同步参考个股、板块和大盘 | 数据不足时给出可解释状态，不产生异常误判 |
| 基本面分析 | P1 | 对标的进行 thesis_intact、material_risk、risk_flags、fundamental_score 结构化分析，并可调用基本面 RAG | 风险点进入 Trader 计划与报告 |
| 交易计划生成 | P0 | 对可行动机会生成结构化计划 | 计划包含方向、入场、止损、目标、仓位、持有周期、失效条件 |
| v2 风控限额 | P0 | 对目标权重执行资格门槛、单标的上限和组合总敞口 clamp | 资格不合格保持当前仓位；超限削减为 final weight，削减部分留作现金 |
| Portfolio Manager | P0 | 将风控后的 final weight 转为组合层面建议 | 仅生成建议和 confirmation_required 状态，不提交券商订单 |
| 报告与审计 | P0 | 每次运行生成节点状态、阶段报告和审计报告 | run_status.json 可查询，run_audit.md 包含节点、报告、输入输出摘要 |
| RAG 记忆 | P1 | 从历史复盘中检索最多 5 条相关记忆作为上下文 | 记忆只作为历史参考，不覆盖实时行情和 v2 风控限额 |
| Web UI | P1 | 提供订阅池、运行控制和结果查看三栏工作台 | 用户能启动任务、轮询进度、查看报告 |
| CLI | P1 | 支持单标的、多标的、全订阅、交互选择和分析模块选择 | 命令行返回 output_dir 和 audit_path |

## 8. 关键规则设计

机会状态：

- observing：默认观察状态，暂未出现明确入场优势。
- near_opportunity：上涨趋势中接近支撑区域，但尚未满足完整行动条件。
- actionable：上涨回调接近支撑，且收益风险比达到阈值。
- risk_elevated：趋势走弱或跌破关键趋势参考。
- not_compatible：与用户画像或交易约束不匹配。

Risk Manager v2 规则：

- 交易机会必须来自订阅池，否则保持当前仓位不动。
- 仅允许用户画像中的市场类型。
- 禁止杠杆和期权，命中则保持当前仓位不动。
- 每个标的目标权重不得超过 `max_single_position_weight`。
- 组合 gross exposure 不得超过 `max_gross_exposure`，超出时等比例缩放目标权重。
- 风控削减的敞口不重新分配给其他标的，保留为现金。

执行状态：

- alert_only：计划仅用于观察或提醒，不是订单候选。
- portfolio_decided：Portfolio Manager 已生成组合层面的最终建议。
- confirmation_required：Live 模式下需要用户显式确认。

## 9. 数据与系统输入输出

主要输入：

- 用户订阅池：symbol、market_type、status、reason、target_action。
- 用户画像：交易风格、风险偏好、允许市场、禁用品种、仓位和回撤限制。
- 市场数据：OHLCV 价格序列。
- 组合快照：当前回撤、持仓权重。
- 新闻情绪、关键事件和基本面评分。
- 历史交易记忆：JSONL distilled memory。

主要输出：

- 新闻情绪评分与关键事件预警。
- 个股、板块和大盘三维技术位置分析结果。
- 基本面分析报告。
- 结构化交易计划。
- 风险检查结果。
- Portfolio Manager 决策状态。
- 用户解释报告。
- run_status.json 和 run_audit.md。

## 10. 交互设计

Web UI 采用三栏工作台：

- 左栏：订阅列表，支持新增、勾选、修改状态、填写关注理由和目标动作。
- 中栏：运行分析，支持手动标的、分析模块、交易日期、回看天数、组合模式。
- 右栏：结果区，展示运行状态、节点进度、错误信息、报告 tab 和报告正文。

设计原则：

- 信息密度优先，适合反复扫描和决策。
- 执行状态必须明显暴露，避免用户误以为系统已真实下单。
- 报告以 Markdown 文本呈现，便于复制、归档和复盘。

## 11. 非功能需求

安全性：

- 默认模拟执行。
- Live 执行必须显式确认。
- UI 中 live portfolio 仅作为只读上下文。
- v2 风控限额不可被 LLM 输出绕过。

可靠性：

- 每个运行节点写入状态，失败时保留错误。
- 价格数据缺失时给出观察或未知状态，不生成无依据交易结论。
- 报告路径和 run_id 做安全校验，避免越权读取。

可解释性：

- 每个节点产出 trace event。
- 报告记录输入、输出、路由原因、规则命中和警告。
- 用户解释报告来自同一份结构化状态，避免报告与实际决策不一致。

可扩展性：

- Agent 模块化，可独立选择和替换。
- 数据适配器独立，可扩展更多行情源。
- 记忆存储使用 JSONL，便于后续迁移到向量库或数据库。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 用户误认为系统会自动盈利 | 法务与信任风险 | 明确定位为辅助决策，不承诺收益 |
| LLM 产生不稳定建议 | 决策质量风险 | 用结构化模型和硬规则约束输出 |
| 行情或新闻数据不完整 | 判断偏差 | 数据缺失时降级为观察状态，并在报告说明 |
| 用户绕过风控追涨 | 资金风险 | 资格门槛、单标的上限和组合总敞口 clamp 不可被 LLM 覆盖 |
| Live 模式误操作 | 交易风险 | 默认 simulation，Live 需要显式确认，UI 不提供自动下单 |

## 13. 迭代路线

短期：

- 修复 UI 中文文案编码显示问题。
- 增加报告摘要卡片，让用户更快看到行动结论。
- 增加更多单元测试覆盖 UI 关键路径和风险规则边界。

中期：

- 引入通知能力，例如接近支撑位时提醒。
- 为不同交易画像提供模板，例如保守型、成长型、ETF 轮动型。
- 增加回测视图，验证新闻情绪、三维技术面和基本面评分的历史有效性。

长期：

- 将记忆系统升级为可检索复盘知识库。
- 支持多账户、多组合维度的风险视图。
- 如未来扩展 broker adapter，必须继续保持人工确认边界，并且不得绕过 Risk Manager final weight。
